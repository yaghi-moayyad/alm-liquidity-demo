Authenticated API. Browser clients use Django sessions and CSRF. Integration clients can use a DRF token locally; use HTTPS and the bank’s identity platform for deployment.

Start a calculation

Get the synthetic input, then POST it to create a run. HTTP 202 returns a run ID immediately. Poll until terminal status. Runs and their input snapshots survive a restart.

python manage.py drf_create_token YOUR_USERNAME

# Substitute the token printed by the command:
curl -H "Authorization: Token YOUR_TOKEN" http://127.0.0.1:8000/api/v1/sample -o input.json
curl -X POST http://127.0.0.1:8000/api/v1/runs \
  -H "Content-Type: application/json" \
  -H "Authorization: Token YOUR_TOKEN" \
  -H "Idempotency-Key: example-run-001" --data-binary @input.json

{"id": "...", "status": "queued", "status_url": "/api/v1/runs/..."}

Use the returned ID in subsequent calls. Use an Idempotency-Key to deduplicate retries. Identical input with the same key returns the existing run (HTTP 200); changed input returns HTTP 409. Keys are scoped to the authenticated user.

OpenAPI contract

Download the generated OpenAPI schema · Browse the DRF run API · Django admin

The schema is generated from DRF views and serializers. Monetary outputs are decimal strings. Run status and detailed cash flows are stored through the Django ORM, with migrations.

Cash-flow filters: contract_id, currency, product, offset, limit (maximum 1,000).

Statuses: queued → running → completed / completed_with_exceptions / failed_validation / failed. Queued jobs survive restarts. Running jobs interrupted by a crash require the explicit recover_runs management command after stopping the old worker. Configuration errors return HTTP 400; invalid contracts become result exceptions. Error responses use {"error":"message"}.

Contract input

{
  "entity": "jordan-mock",
  "as_of_date": "2026-09-16",
  "bucket_days": [1, 7, 14, 30, 90, 365],
  "contracts": [{
    "contract_id": "LN-001",
    "product": "loan",
    "currency": "JOD",
    "principal": "120000.000",
    "annual_rate": "0.06",
    "rate_type": "fixed",
    "repayment": "equal_principal",
    "day_count": "ACT/365F",
    "frequency_months": 3,
    "accrual_start": "2026-07-01",
    "next_payment": "2026-10-01",
    "maturity": "2027-07-01",
    "end_of_month": false
  }]
}

Required for all contracts: contract_id, product, currency, principal. Dated contracts additionally require annual_rate, repayment, day_count, frequency_months, accrual_start, next_payment and maturity. Optional defaults: rate_type=fixed, end_of_month=false, status=performing.

Products: loan, bond and interbank_asset are inflows; term_deposit and borrowing are outflows. demand_deposit is an undated liability disclosure, accepting balance fields only. Unknown fields are rejected per contract to avoid silently ignoring terms.

Currencies: JOD (3 decimals), USD / EUR / GBP (2 decimals). Rates use decimals, not percentages. Payment dates must be strictly after the reporting date. No holiday adjustments. Bucket boundaries are exact elapsed calendar days, not calendar months.

Currency amounts in result JSON are decimal strings. Dates are YYYY-MM-DD. Inputs: maximum 2,000 contracts and 4 MB. No bulk bank-data connector is included yet.
